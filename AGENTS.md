# AGENTS.md

This repo is `pdt-meltano`, a Meltano utility built with the Meltano EDK. It deploys the job schedules of a Meltano project through `pdt-cli`. It holds no cloud code: every cloud action is a `pdt` command run on the pdt project it writes into `$MELTANO_SYS_DIR_ROOT/utilities/$MELTANO_UTILITY_NAME/pdt/<environment>/<Meltano project folder name>/`, one for each Meltano environment. pdt names a project after its folder in events and alerts, so the last folder and the image path `/srv/<Meltano project folder name>` (the generated Dockerfile's `COPY` and `PDT_PROJECT`) both have the Meltano project's name. Each app name is `<schedule>-<environment>`. Users type schedule names in every command; `Pdt.invoke` changes the first schedule name of an `APP_COMMANDS` command to its app name before it calls pdt. Keep that project out of `$MELTANO_SYS_DIR_ROOT/run/`: `meltano install` deletes everything in a plugin's run folder, and the project holds the deployed list that `destroy` needs. A cloud feature starts in pdt, not here.

- The `config_dir` setting names the folder of the shared `pdt.yml`, by default `$MELTANO_PROJECT_ROOT/orchestrate/pdt`. It holds every key other than `platform:`, such as `alerts:`. pdt edits that file itself: `alerts` commands run pdt with `PDT_PROJECT` set to that folder, and pdt-meltano copies alerts from a deploy's offer with pdt's `save_root_alerts`. Do not rewrite the file with `yaml.safe_dump`, because that deletes the user's comments.
- Each app's `config.yml` lists under `env: optional:` only the env names its job reads: the setting env names of the job's plugins (one `meltano config print --format=env` call for each plugin; Meltano hides only sensitive values, and pdt-meltano keeps only the names) and each `$NAME` in those plugins' blocks and in the project settings of `meltano.yml`. Only `deploy` and `secrets` (`SECRET_COMMANDS`) find them; other commands keep the list in config.yml. Never log or save a value from that output.
- `pdt_meltano/extension.py` reads the schedules with `meltano schedule list --format=json` and writes the pdt project. `RUN_PY` and `DOCKERFILE` are the files every app gets.
- Tests need no network, no Meltano install, and no cloud account.
